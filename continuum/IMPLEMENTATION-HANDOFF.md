## 2. What to build

One Windows x64 .NET 10 console executable, `LocalMCPServer`, with two entry modes:

| Mode | Started by | Purpose |
|---|---|---|
| default (no arguments) | Claude Code, as an MCP stdio child process | serves the 11 MCP tools below; stdout carries MCP protocol messages only, diagnostics go to stderr, structured and redacted |
| `provision` subcommand | the developer at an interactive console | creates an alias and prompts for its secret; the only way a credential enters the system |

Three services run inside it (all `deployedAs: LocalMCPServer`). Each store has exactly one writing service.

| Service | Handles | Reads | Writes | Invokes on SQL Server | Constrained by |
|---|---|---|---|---|---|
| `ConnectionRegistry` | `ProvisionConnection` (console), `RemoveConnection`, `ListConnections` | CredentialVault, ConnectionCatalog | ConnectionCatalog | none | SecretRedaction, ApprovedEnvironmentsOnly |
| `QueryGateway` | `ValidateSql`, `ExecuteSql`, `StartInvestigation`, `RecordFinding`, `GetInvestigation` | CredentialVault, ConnectionCatalog, InvestigationHistory | InvestigationHistory | `Tsql.ExecuteSelect` | SelectOnlyAllowlist, QueryBudgets, SecretRedaction, ApprovedEnvironmentsOnly |
| `KnowledgeService` | `InspectSchema`, `SearchKnowledge`, `ProposeRelationship`, `ReviewRelationship` | CredentialVault, ConnectionCatalog, KnowledgeStore | KnowledgeStore | `Tsql.ReadCatalog` | SecretRedaction, ApprovedEnvironmentsOnly |

**The credential vault has no writing service.** ADL forbids a service `writes` edge to a `secret-store` (`adl/architectural/secret-store-write`). In code, the `provision` console flow places the DPAPI-protected secret in the vault. Services only ever read it, and nothing reachable over MCP can write or return it.

## 3. The MCP tool surface

Tool names are fixed. Use them verbatim in code and in `acceptance/adapter.mjs`. Each maps to one declared message whose payload and result records are declared in the model. Treat those records as the minimum field set of each tool's JSON schema; the exact JSON schema is an implementation choice.

| MCP tool | Model message | Kind | Payload → result | Handler |
|---|---|---|---|---|
| `connection_list` | `ListConnections` | query | `AliasRef` → `ConnectionList` | ConnectionRegistry |
| `connection_remove` | `RemoveConnection` | command | `AliasRef` | ConnectionRegistry |
| `schema_inspect` | `InspectSchema` | query | `SchemaRequest` → `SchemaSnapshot` | KnowledgeService |
| `sql_validate` | `ValidateSql` | query | `SqlRequest` → `ValidationVerdict` | QueryGateway |
| `sql_execute` | `ExecuteSql` | query | `SqlRequest` → `QueryEvidence` | QueryGateway |
| `investigation_start` | `StartInvestigation` | command | `InvestigationRequest` (returns the new `investigationId`) | QueryGateway |
| `investigation_record` | `RecordFinding` | command | `InvestigationEntry` | QueryGateway |
| `investigation_get` | `GetInvestigation` | query | `InvestigationRef` → `InvestigationRecord` | QueryGateway |
| `knowledge_search` | `SearchKnowledge` | query | `KnowledgeQuery` → `KnowledgeResults` | KnowledgeService |
| `knowledge_propose` | `ProposeRelationship` | command | `RelationshipProposal` (enters as `proposed`) | KnowledgeService |
| `knowledge_review` | `ReviewRelationship` | command | `RelationshipReview` | KnowledgeService |

No tool accepts or returns a credential. Provisioning is **not** an MCP tool. `knowledge_review` records the developer's explicit decision; the agent must not call it on its own initiative (BDL `ReviewRelationship` may be performed by the Investigator only).

`sql_execute` returns result rows to Claude Code but **does not persist them**. History keeps the query id, exact SQL, alias, timestamps, row count and truncation flag.

## 4. Technology (from the bindings, not invented here)

| Concern | Choice | Bound on |
|---|---|---|
| OS / runtime / language | Windows x64, .NET 10 (`net10.0`), C# | LocalMCPServer |
| Agent protocol | MCP over stdio | LocalMCPServer |
| SQL access | Microsoft.Data.SqlClient | QueryGateway, KnowledgeService |
| SQL validation | Microsoft.SqlServer.TransactSql.ScriptDom, fail-closed allowlist of one bounded SELECT | QueryGateway |
| Credentials | Windows DPAPI CurrentUser, current-user-only file ACL | CredentialVault, ConnectionRegistry |
| Local persistence | System.Text.Json, atomic replace, single writer | InvestigationHistory, KnowledgeStore, ConnectionCatalog |
| Tests | xUnit plus disposable SQL Server fixture databases | (not a bindable element) |

`atomic-json-files` claims `retention-honored`, `erasure-capable`, `access-controlled` and `auditable`, so the code must deliver all four for every JSON store: an enforced retention rule, a way to delete an entry, current-user-only ACLs, and audit events for writes.

The MCP SDK library is not fixed by the bindings. Choosing one is an implementation decision. Record it in the README of the source tree, not in the model.

## 5. Safety rules (non-negotiable)

- **SelectOnlyAllowlist.** Parse with ScriptDom. Accept exactly one statement in one batch that is a SELECT with no INTO, no dynamic execution, no linked-server four-part names, no OPENROWSET/OPENQUERY/OPENDATASOURCE, no cross-database three-part names, no WAITFOR, no table, view or column outside the alias's approved scope (recorded in ConnectionCatalog at provisioning; B04 `forbidden-table`, `forbidden-column`), and no unrecognised AST node. Reject everything else before it reaches SQL Server, with an audited reason. Never assume a SELECT is safe because it parses.
- **Read-only principal.** Every alias connects as a dedicated least-privilege read-only SQL login. Prove write denial at the database level independently of the validator (integration test with the validator bypassed; acceptance step `sql.principal-denies-writes` in B03).
- **QueryBudgets.** Timeout, rows, bytes, concurrency and per-investigation query count. Recommended defaults are in `development-package.json` `controls` (`SQL_TIMEOUT_SECONDS=15`, `MAX_QUERY_ROWS=500`, `MAX_RESULT_BYTES=1048576`, `MAX_CONCURRENT_QUERIES=2`, `MAX_QUERIES_PER_INVESTIGATION=50`). They are configurable recommendations, not architecture. Exceeding one cancels, refuses or truncates with an explicit flag, plus an audit event.
- **SecretRedaction.** No secret in any MCP result, error, stderr diagnostic, history or knowledge entry, or plaintext file. Scenario B09 searches all of them.
- **ApprovedEnvironmentsOnly / ProductionDataApproval.** Fixtures and approved development data only. **No production connection until the data owner approves the data classifications and environment** (BDL `SensitiveDataPolicy` is open and owned by the data owner).
- **SeparatePerDatabaseQueries.** One alias per query. Correlation across databases happens in Claude Code over separate results.
- **SafeFailure.** Errors are actionable and sanitized; never return fabricated or stale results as current.
- **Untrusted content.** Database values, object names and imported documents are untrusted data, both to the server and to the agent. The server never acts on their content: no value becomes SQL, a path or a command. Results are returned as data, never merged into tool descriptions or instructions.

## 6. Verifying the result

| Gate | Command | Done when |
|---|---|---|
| Package consistency | `continuum package check continuum` | `intact` |
| Acceptance | `continuum package run continuum` | 12 / 12 pass against the **real** executable |
| Unit and integration tests | `dotnet test` | green, including the negative SQL corpus and DB-level write denial |
| Architecture gate | `continuum guard ci` (runs in GitHub Actions) | PASS |

`acceptance/adapter.mjs` is the official scaffold: 46 step stubs, each failing loudly with its key and arguments. Bind every step against the real `LocalMCPServer` process over stdio, with disposable SQL Server fixtures. Never bind a step to an in-memory fake that returns success. The two `b12` steps `mcp.stdout-protocol-only` and `mcp.tool-surface-exact` check the protocol-only stdout rule and the exact 11-tool surface.

Until the implementation passes the suite, `continuum guard pre-push` and the CI gate report FAIL (implementation drift: 12 scenarios fail). That is the expected starting point, not a package defect.

## 7. Definition of done

- All 12 acceptance scenarios pass against the real executable; `continuum package check` is intact; the CI architecture gate is green.
- `dotnet test` is green, with the negative corpus from B03/B04 and the independent read-only principal test.
- No web UI, chat surface, embedded LLM, provider abstraction, SQLite, linked server, hosted service or Continuum runtime dependency.
- No production connection without recorded data-owner approval.

## 8. What the model leaves to you, and how to ask for more

Left to the implementation: MCP tool JSON schemas beyond the declared records, the exact allowlist grammar, budget numbers (recommended defaults given), retention periods, file locations, logging format, and the MCP SDK library.

If the code needs an answer the model does not give, do not improvise architecture. Write `continuum/gaps/<YYYY-MM-DD>-<slug>.md` and stop for the owner. The `implement-against-architecture` skill drives this. A model change is an `.adl-change` pinned to the changeState above.
